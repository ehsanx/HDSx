# Assignment 1: Modern Workflows

## Purpose

This required Complete/Incomplete checkpoint confirms that your personal course
workspace works before the analysis weeks begin. You will edit the supplied
root-level Quarto file, render it, commit both source and output, sync the
commit, and submit the repository link.

## Due Timing

Submit by **Monday after the Week 2 class at 4:00 PM**.

## Learning Objectives

- Launch or reopen a Codespace from your personal workspace fork.
- Edit YAML, Markdown, and a simple R code chunk.
- Render a self-contained HTML file and locate it in the Explorer.
- Commit and sync a reproducible change.
- Verify the commit on GitHub and stop the Codespace.

## Inputs

- Personal workspace linked from Canvas
- Root starter: `practice_report.qmd`
- Synthetic practice data: `data/patients.csv`
- Week 2 workflow page

## Tasks

1. Open your personal workspace fork and launch or reopen its Codespace.
2. At the repository root, open the supplied `practice_report.qmd`.
3. Change the YAML `author` field to your name.
4. Add a `## My Notes` section with 2–3 sentences about what you learned.
5. Use at least one Markdown feature such as bold text, italics, or a list.
6. Modify an existing code chunk or add one small R calculation.
7. Render the document and confirm `practice_report.html` appears beside the
   source file and contains your edits and chart.
8. In Source Control, inspect the changes and stage both
   `practice_report.qmd` and `practice_report.html`.
9. Commit with a clear message, sync, and verify the commit on GitHub.
10. Stop the Codespace when finished.

## AI-Use Expectations

AI may help explain an error or Quarto syntax. If you use AI, add one sentence
under `## My Notes` naming what it helped with and how you verified the result.
No separate AI-use file is required for A1.

## Reproducibility Requirements

- Work in the supplied personal workspace rather than the read-only course book.
- Keep `practice_report.qmd` and `practice_report.html` at the repository root.
- Use only relative paths.
- Commit the required rendered HTML with its source.

## What To Submit

Submit your personal workspace repository link on Canvas. The linked, synced
commit must contain these two root-level files:

- `practice_report.qmd`
- `practice_report.html`

No reflection file, commit-evidence file, screenshot, or nested A1 submission
folder is required. The repository link and Git history provide the commit
evidence.

## Grading Checklist

Complete:

- the root starter contains the required YAML, Markdown, and code edits;
- `practice_report.html` renders from that source and is committed;
- paths are relative;
- the final commit is synced and visible through the submitted link.

Needs work:

- either required root file is missing;
- the rendered output does not match the source;
- the code does not render or uses a machine-specific path;
- the final change is not synced.

## Definition of Done

A1 is done when the Canvas link opens your synced personal workspace and the
root-level source and rendered HTML show the completed workflow check.
