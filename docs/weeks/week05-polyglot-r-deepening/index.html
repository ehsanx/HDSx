Python with AI

Overview

Summary: You know how to wrangle data in R (Week 3) and track your history with Git (Week 4). This week, you’ll use Large Language Models to translate your existing R skills into Python—running everything inside your GitHub Codespace. You don’t need to become a Python expert; you need to be great at directing the AI and verifying the output.

Learning Objectives:

  • Explain when and why a health data scientist might choose Python over R (and vice versa).
  • Create and run a Python Jupyter Notebook (.ipynb) and a Python script (.py) in your Codespace.
  • Use the VS Code Variables pane and Data Viewer to inspect Python data.
  • Map R mental models to Python equivalents (dplyr → pandas, ggplot2 → seaborn/matplotlib).
  • Manage a reproducible Python environment using requirements.txt.
  • Use reticulate to call R from Python (or vice versa) for a simple interoperability demo.
  • Avoid “Frankenstein code” via the One Step, One Cell AI workflow.
  • Apply Week 4 Git skills to track Python translations with meaningful commits.

Connection

Week 4 made small changes reviewable. This week checks whether the same dataset gives the same answer when you move between R and Python. Next week you will turn those summaries into clearer visual explanations.

Case Study Data Analysis

The NHANES Health Equity data spine now supports code-reading, EDA, visualization, and reproducibility checks. Use the cached CSV/RDS for routine class work; a CDC retrieval script exists for advanced users.

  • Cached RDS: examples/nhanes-equity/data/nhanes_equity_v6.rds
  • CSV snapshot: examples/nhanes-equity/data/nhanes_equity_v6.csv
  • Case-study README: examples/nhanes-equity/README.md

The default classroom path is to use the cached data so the analysis work is reproducible without internet access.

library(readr)
library(dplyr)

candidate_paths <- c(
  "examples/nhanes-equity/data/nhanes_equity_v6.csv",
  "../../examples/nhanes-equity/data/nhanes_equity_v6.csv"
)

nhanes_path <- candidate_paths[file.exists(candidate_paths)][1]
if (is.na(nhanes_path)) {
  stop("Could not find examples/nhanes-equity/data/nhanes_equity_v6.csv")
}

nhanes_analysis <- read_csv(nhanes_path, show_col_types = FALSE)

nhanes_analysis |>
  summarise(
    rows = n(),
    missing_bmi = sum(is.na(BMI)),
    missing_income = sum(is.na(IncomeGroup))
  )

nhanes_analysis |>
  filter(!is.na(BMI), !is.na(IncomeGroup), Age >= 20, Age <= 80) |>
  group_by(IncomeGroup) |>
  summarise(
    n = n(),
    mean_bmi = round(mean(BMI), 1),
    .groups = "drop"
  )

In-Class Activity

  • Load examples/nhanes-equity/data/nhanes_equity_v6.csv in R and Python.
  • Compare row counts and column names across the two languages.
  • Choose one summary, such as mean BMI by sex, and check whether R and Python agree.
  • Treat any mismatch as an audit prompt: check data types, missing values, and grouping logic before changing code.

python1.qmd Concepts: Python vs R—When and Why?

Two Languages, One Codespace

Both R and Python are first-class citizens in your GitHub Codespace. You are not choosing one forever; you are learning when each is the better tool.

Strength R Python
Statistical modeling & tidyverse-style wrangling Mature ecosystem (dplyr, ggplot2, lme4) Possible, but more verbose
Machine learning & deep learning Growing (tidymodels, torch) Dominant (scikit-learn, tensorflow, pytorch)
Dashboards Shiny (Week 8) Streamlit, Dash
General-purpose scripting & automation Less common Very common

Bottom line for this course: R remains your primary analysis language. Python is introduced so you can (a) read and adapt Python code you encounter in the wild, (b) leverage Python-only libraries when needed, and (c) demonstrate bilingual fluency in your portfolio.

Notebooks vs Scripts

  • Notebook (.ipynb): Best for exploration, teaching, and narrative analysis. Cells run interactively; output appears inline.
  • Script (.py): Best for reusable utilities, automation, and clean code. Runs top-to-bottom.

In this week’s activities, you will work primarily in a notebook but also create one short .py script to see the difference.

python2.qmd Setup: Jupyter in Codespaces

Create and Run a Notebook

  1. New file: VS Code Explorer → New File → name it translation.ipynb.
  2. Select kernel: Notebook toolbar → Select Kernel → choose the recommended Python environment.
  3. First cell: Type print("Hello from Python") and press Shift + Enter.

The Variables Pane and Data Viewer

After running a cell that creates a variable, open the Variables pane (notebook toolbar). Double-click any DataFrame to open an “Excel-like” grid view—your best friend for verifying that data loaded correctly.

Tip

If notebook features (Variables, Data Viewer) are missing, ensure the Jupyter extension is enabled in your Codespace. Check the Extensions panel (block icon on the left sidebar).

python3.qmd Packages and Environment Hygiene

R library() → Python import

R Python equivalent
library(dplyr) / tidyverse import pandas as pd
library(ggplot2) import seaborn as sns or import matplotlib.pyplot as plt
library(readr) pd.read_csv(...) (built into pandas)

Why requirements.txt Matters

Your course Codespace comes with core packages pre-installed. But your term project must run in a fresh Codespace. If you add a package, you must record it:

  1. Open (or create) requirements.txt in your repo root.
  2. Add the package name and version:
pandas==2.2.0
seaborn==0.13.2
  1. To install from this file: the Codespace setup script runs pip install -r requirements.txt automatically on launch.
Warning

Reproducibility rule: Never install packages by running pip install X in the terminal and forgetting about it. Always update requirements.txt. This is the Python equivalent of R’s renv—you will see renv in Week 11.

Documenting Your Decisions

When you choose a package or approach, add a brief Markdown cell in your notebook explaining why. For example: “Using seaborn here because it produces cleaner default aesthetics for categorical comparisons than matplotlib alone.” This habit satisfies the reproducibility expectation and helps your future self (and your grader).

python4.qmd Translation Traps: What Breaks When You Switch Languages

Trap 1: The Zero-Index

  • R indexes from 1; Python indexes from 0.
    • R: my_vec[1] → first element
    • Python: my_list[0] → first element
  • Python slicing is end-exclusive: df.iloc[0:5] returns rows 0–4 (five rows total).

AI Prompt:

Translate my_vector <- c(10, 20, 30); my_vector[1] to Python. Explain 0-based indexing and why my_list[0:2] returns only two elements.

Trap 2: The Indentation Trap

  • R uses {} to define code blocks; Python uses indentation (spaces). Misaligned spaces cause IndentationError.

AI Prompt:

Translate this R if/else block to Python. Explain how indentation replaces {} and show correct formatting for a Jupyter cell.

Trap 3: Assignment and Equality

  • R uses <- for assignment (though = works too); Python uses =.
  • Both use == for comparison, but Python’s None check is is None, not == None.

python6.qmd Reading Tracebacks (Bottom-Up)

Python errors display a Traceback—a stack of function calls. The most useful information is at the bottom.

Example

---------------------------------------------------------------------------
FileNotFoundError                         Traceback (most recent call last)
Cell In[3], line 2
      1 import pandas as pd
----> 2 data = pd.read_csv("Data/patients.csv")

FileNotFoundError: [Errno 2] No such file or directory: 'Data/patients.csv'

Reading it: The bottom line tells you the file was not found. The capital “D” in "Data/" is the culprit—file paths are case-sensitive on Linux (your Codespace runs Linux).

AI Prompt:

Here is a Python Traceback from my Codespace: [paste]. Read it bottom-up, explain the error in one sentence, and give corrected code.

python7.qmd The AI Workflow: One Step, One Cell

Rule 1: One Step, One Cell

Ask your AI for one atomic step at a time: load data, then preview, then filter, then summarize. Run and verify each cell before requesting the next. This prevents “Frankenstein code”—a giant block of AI-generated code where one hidden error cascades through everything.

Rule 2: Reverse Translation

When AI gives you unfamiliar Python, paste it back and ask:

Explain this Python code step by step as if translating it back to R’s dplyr. What does each line do?

This converts opaque Python into your familiar mental model.

Rule 3: Parity Audit

After each translated step, compare Python output to your R output:

Check R Python
Row count nrow(df) len(df) or df.shape[0]
Column names names(df) df.columns.tolist()
Unique levels unique(df$col) df['col'].unique()
Summary stats summary(df$col) df['col'].describe()

If the numbers don’t match, something went wrong in translation. Fix it before moving on.

python8.qmd Interoperability: A Taste of reticulate

Why Interoperability?

Sometimes you don’t want to rewrite everything. The R package reticulate lets you call Python from an R session (and access Python objects as R objects). This is conceptual exposure—you are not expected to build full projects this way, but you should know it exists.

Demo (in an R Quarto document or R console)

library(reticulate)

# Run a line of Python from R
py_run_string("import pandas as pd; df = pd.read_csv('data/patients.csv')")

# Access the Python object in R
py_df <- py$df
head(py_df)
Note

This demo runs inside your Codespace where both R and Python are available. You do not need to install anything locally. The goal is awareness: when you encounter a Python-only package in a future project, you know you can call it from R without rewriting your entire pipeline.

python9.qmd Creating a Python Script (.py)

Not everything belongs in a notebook. When you have a reusable utility (e.g., a data-cleaning function), a .py script is cleaner.

Walkthrough

  1. In VS Code Explorer, create a new file: helpers.py.
  2. Write a simple function:
import pandas as pd

def load_and_preview(filepath, n_rows=5):
    """Load a CSV and return the first n rows."""
    df = pd.read_csv(filepath)
    print(f"Loaded {len(df)} rows, {len(df.columns)} columns")
    return df.head(n_rows)
  1. In your notebook, import and use it:
from helpers import load_and_preview

preview = load_and_preview("data/patients.csv")
preview
  1. Stage and commit both files with a descriptive message.
Tip

When to use which: Notebook for exploratory analysis and narrative. Script for functions you will reuse across notebooks or projects.

python10.qmd Git Integration: Track Your Translations

Apply your Week 4 skills:

  1. After completing each major translation step, stage and commit with a meaningful message.
  2. Use AI to draft commit messages from your diffs (Week 4, git6b.qmd).
  3. If AI-generated code breaks your notebook badly, use Discard Changes (curved arrow in Source Control) to revert to your last commit.
Warning

Jupyter notebooks and Git: .ipynb files contain cell outputs (images, tables) in their JSON. This makes diffs noisy. Consider clearing outputs before committing: Command Palette → Notebook: Clear All Outputs → then stage and commit. This keeps your diffs readable.

python13.qmd Practice Exercise: The Bilingual Translation

Task: Create a Python version of your Week 3 R analysis inside your Codespace.

Workflow

  1. Create translation.ipynb and select the Python kernel.
  2. Use your LLM to translate your R steps to Python (pandas) one cell at a time.
  3. After each cell, verify output using the Variables / Data Viewer and run parity checks (row count, column names, summary stats) against your R results.
  4. Extract at least one reusable function into a helpers.py script. Import and use it in your notebook.
  5. Add a Markdown cell at the top documenting: which AI model you used, and any decisions you made (e.g., “Used seaborn instead of matplotlib for cleaner default bar charts”).
  6. Clear notebook outputs (Command Palette → Notebook: Clear All Outputs).
  7. Git: Stage both files, write a professional commit message (use AI to draft it from the diff), ✔ Commit, then Sync Changes.
